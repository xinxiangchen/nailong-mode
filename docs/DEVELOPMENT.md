# 开发与实现说明

[← 返回奶龙上身](../README.md)

## 体感与模型调整（2026-10-29）

- 双手优先按姿态手腕匹配所属手臂，交叉手、托腮越过中线时不再仅按画面左右交换手型；无可靠姿态时保留画面位置兜底。
- 3D 重定向过滤低可见度、异常臂长和退化肩线，失败时继续使用二维角度。
- 手臂使用随动作幅度变化的平滑：小幅抖动保持稳定，大幅抬手加快响应；减少渲染阶段的重复延迟。
- 摄像头同一帧只推理一次；超过 500 毫秒没有新结果时，角色和状态提示不再沿用过期识别。
- 真人跟踪时取消挑战预设的额外躯干和仰头角度；识别到手指时按实际开合度驱动，不再被预设手型压缩。
- 按三张参考图改为小头、宽肩、圆腹：头部与五官统一缩小 22%，撤销上一版腹部收窄，恢复圆润的腹部宽度与厚度；同步调整下巴蒙皮、肩根和抱头时的手部落点。捧腹演示略微前倾。

验证：`npm test` 包含交叉双手、单手越中线、3D 低可信度/异常臂长回退、快速动作与角度跨界测试。浏览器自动化检查三种挑战演示、真人中性头部映射和二维降级；另实测头部截面宽度缩放为 0.78、腹部截面保持 1.0，并检查低头、仰头、转头的渲染；真人摄像头下的光照、遮挡与端到端延迟仍需现场体验确认。

### 头颈绑定与远距离识别补充

- 保持小头和圆腹，沿蒙皮权重将头颈抬高 0.20 模型单位；侧后方颈部和头部使用更宽的权重过渡带，缓解转头、低头时的折角。托腮、抱头的手部偏移随头颈高度调整。
- 摄像头优先请求 1920×1080、30fps（实际规格由设备决定）。身体和手仍识别整幅画面；根据可靠的姿态面部点，将小脸区域裁剪到 512×512 单独识别，再恢复全画面坐标和深度。
- 裁剪识别失败时交替尝试整图重捕获，不复用旧表情计分。脸部像素不足时提示向前半步；推理完成后才开始计算结果是否过期。
- 修正 16:9 等宽高比下的几何俯仰换算，放宽远距离头部几何兜底门槛；裁剪输出不混用整图相机朝向矩阵。

测试使用 MediaPipe [官方示例人像](https://storage.googleapis.com/mediapipe-assets/portrait.jpg) 缩放到 1280×720 画面：人像高度 600、400、260 像素时，整图检测未检出人脸，局部路径均恢复表情输出；180 像素时姿态也无法检出，仍需靠近。这里的人像高度不是脸部高度，也不能换算成统一的实际距离。单元测试覆盖裁剪边界、坐标/深度恢复、丢脸处理和不同距离、宽高比下的头部俯仰。

### 大笑与捧腹评分修正

捧腹和仰天的表情采用单向达标评分：张嘴 0.55、咧嘴 0.50、笑眼 0.38 达标后不再因幅度更大扣分；不要求挑眉。三项分别占表情组的 45%、35%、20%。这些是游戏容错阈值，不是每个人的个性化标定；思考挑战保持原来的闭嘴、睁眼要求。

捧腹以手肘自然下垂、小臂向腹部内收为目标。屏幕左/右上臂接受 −40°～15° / −15°～40°，小臂接受 35°～105° / −105°～−35°；范围外逐渐扣分。小臂两侧各占肢体组 35%，上臂各 10%，身体侧倾 10%，因此仅双臂下垂不能拿到高肢体分。前倾仍用于模型映射，不要求固定弯腰角度。同步调整捧腹模型手臂落点和肘部偏移。

捧腹、仰天如果缺少任一侧手臂的姿态信息，总分最高 85，不能触发完美模仿，并提示肩膀、手肘和手腕入镜。HandLandmarker 的手指识别依旧不计分。

## 技术实现

```
摄像头
  ├─ MediaPipe FaceLandmarker ──> 52 个 blendshape + 478 个面部关键点
  ├─ MediaPipe PoseLandmarker ──> 33 个姿态关键点
  └─ MediaPipe HandLandmarker ──> 每只手 21 个关节点（最多 2 只）
        ↓
   特征提取（metrics.js）
        ↓
   平滑 + 挑战目标相似度评分（scoring.js）
        ↓
   3D 奶龙（nailong3d.js：SkinnedMesh + IK 手臂）
        ├─ WebGL 不可用 / ?no3d=1 → Canvas 2D 奶龙（avatar.js）
        ↓
   实时 HUD（app.js）
```

### 3D 形象与绑定

`js/nailong3d.js` 用 Three.js 程序化建模了一只奶龙，不依赖外部 GLB：

- **身体**：自建环形放样（per-ring 半宽 / 半深 / 前后偏移 + 超椭圆截面）得到上窄下宽的连续软糖体，而不是拼球；奶白色肚皮直接写在顶点色里，跟着身体一起变形。髋、脊柱、胸、颈、头五根骨骼用高度混合的权重控制弯腰、呼吸、扭头和点头。
- **身体旋转**：肩线和身体朝向换算出的转身、前倾、侧倾，按髋 → 脊柱 → 胸逐级分配；脚留在根节点上，所以身体转动时脚不会跟着滑走。脖子和头只承担剩余的旋转量，转身看起来是「腰带着胸、胸带着头」。
- **脸**：眼睛、瞳孔、闭眼笑弧、嘴巴、牙齿、舌头全部挂在头骨上。下半张脸有轻微前鼓的短吻，嘴和闭眼线贴着吻部；张嘴度驱动大嘴缩放，眯眼度驱动眼睛压扁和笑弧淡入；头骨旋转会带着整张脸一起动。嘴贴着身体曲面逐点生成，所以五官和脸严丝合缝。
- **下巴**：奶龙没有脖子，嘴的下半截压在胸口上方。这块「下巴」皮肤在正面的权重被提前交给头骨（越靠正脸越早交），所以仰头、转头时脸皮和刚性的五官是同一个角度，黑的嘴不会被黄色的脸顶穿；侧后方仍是胸口权重，转头不会把肩膀拧走。
- **手臂**：MediaPipe 的肩 / 肘 / 腕角度先换算成手腕目标点，再用两节骨 IK 反推肘的位置。可见的手臂是每帧按肩 → 肘 → 腕重建的一整条软管，两端各带一个半球收口：肩根埋进胸腔，手腕那端缩进手掌里。软管自己没有平口，肩膀上也不用再摆一颗球去堵洞，早先那种「撕纸」接缝就消失了。
- **手**：每只手有手腕、四根两节手指和一根两节拇指，`HandLandmarker` 的 21 点开合度直接驱动指节弯曲。手腕关节叠在整体手型里，按「相对手出现时的增量」跟踪：手一出现就记下当时的朝向，之后只把抬腕 / 压腕、左右侧偏的变化量叠上去（屈伸 ±60°、侧偏 ±45°）。前臂自身的转动会先从增量里扣掉，所以整条手臂转一下不会被误判成转手腕；前臂旋转在单目下噪声最大，不再叠加。三个挑战都是 `wristGain: 1`，抬腕 / 压腕会 1:1 反映到奶龙手上。
- **腿**：姿态里的髋、膝、踝角度驱动三段短腿，脚掌和脚趾保持圆润。
- **兜底**：检测不到 WebGL、显卡上下文丢失或请求 `?no3d=1` 时，页面切回原来的 Canvas 2D 形象；3D 加载失败不会影响挑战和打分。

> 3D 形象与手部关节都是代码生成的原创同人建模，没有使用任何外部角色模型或贴图。

### 表情映射

- `jawOpen` + 唇间几何距离 → 奶龙嘴张开的幅度
- `mouthSmileLeft/Right` + 嘴角上扬角度 → 嘴角和腮红
- `eyeSquintLeft/Right` + `cheekSquint` + `eyeBlink` + 眼睛开合几何 → 笑眼 / 弯弯眼
- `browInnerUp` → 眉毛高度
- 双眼连线角度 → 歪头

如果某些 blendshape 在当前设备上不可用，会自动回退到面部关键点几何计算。

### 肢体与手部映射

- 肩 → 肘 → 腕：计算上臂、小臂与竖直方向的夹角，驱动奶龙的手臂
- **单目 3D 重定向**：`PoseLandmarker` 的 `worldLandmarks` 是米制、以髋部为原点的 3D 坐标。先把肩线右轴、肩髋上轴和前向拼成玩家自己的躯干坐标系，再把肩 / 肘 / 腕换算到这个坐标系里，交给手臂 IK。所以手臂的前伸、后摆这些「深度」方向也认得出来，而玩家转身时手臂不会被转两次——和单目动捕驱动机器人用的是同一套思路。髋部不可用时自动退回 2D 角度
- 肩线倾斜 / 双肩前后差 → 身体侧倾 / 转身；肩线俯仰 → 身体前倾
- 头部朝向矩阵（不可用时退回面部关键点几何）→ 脖子与头的剩余偏航 / 俯仰；转头量在躯干坐标系里拆成「身体 + 颈 + 头」三段，身体先转、脖子跟上、头只做残余，前后左右扭头都有明确的方向感
- 手部关键点局部坐标系 + `worldLandmarks` 前臂方向 → 手腕屈伸 / 侧偏的相对增量（前臂旋转不参与）
- 髋 → 膝 → 踝：镜头拍得到时驱动小短腿
- HandLandmarker 的 21 点 → 手指开合（四指 + 拇指），驱动奶龙手指
- 手掌中心 → 与「下巴 / 肚子 / 头侧」的距离；手上有手指时同时计算开合度
- 失去跟踪时头、脖子、身体旋转和四肢会平滑回中，不会停在上一帧的扭头姿势
- 手部模型看不见手时，用姿态关键点里的手腕位置做定位兜底（只影响奶龙的手型，不参与评分）
- 镜像处理：画面按自拍镜面显示，屏幕左侧的手驱动奶龙屏幕左侧的手

### 评分

每个挑战有三组，组权重在 `js/challenges.js` 里：

| 挑战 | 表情 | 肢体 | 歪头 |
|---|---:|---:|---:|
| 奶龙思考 | 79% | 14% | 7% |
| 奶龙捧腹 | 64% | 29% | 7% |
| 奶龙仰天 | 64% | 29% | 7% |

表情、角度使用带「死区」的容差曲线：

```
相似度 = 1                                  （偏差在死区内）
       = 1 - (|偏差| - 死区) / (容差 - 死区)   （逐渐降到 0）
       = 0                                  （超出容差）
```

手部位置和手指开合只用于驱动奶龙的手，不参与相似度评分。

- 检测不到的分组/特征会被剔除并重新分配权重
- 完全看不到手：不扣分，也不影响「完美模仿」
- 捧腹 / 仰天看不到上半身：总分最高 85
- 思考不要求躯干，脸可见即可继续
- 每帧做指数平滑（EMA），避免抖动
- 峰值作为最终成绩；保持 90 分 2 秒触发「完美模仿」

## 常见问题

**摄像头权限被拒绝**
点浏览器地址栏左侧的站点设置图标，把摄像头改成「允许」，再点一次「开始挑战」。

**页面提示请通过 start.ps1 打开**
说明你直接双击了 `index.html`。请关闭页面，双击 `启动奶龙.bat`，使用 `http://127.0.0.1:8899`。

**模型加载失败**
确认 `models/` 和 `vendor/` 目录完整，然后刷新页面或点「重试加载模型」。如果使用了代理/杀毒软件，允许本地端口访问。

**识别很卡**
页面会优先使用 GPU；如果 GPU 不可用会自动切到 CPU，并降低检测频率。现在同时跑脸、姿态、手三个模型，关掉其他占用显卡的程序会有帮助。

**奶龙的手不太跟手**
- 手部动作不计分，但它会让奶龙的手跟着你动
- 让手完整出现在画面里，不要只在画面边缘露一点；出画时奶龙的手会回到默认姿势
- 打开「显示骨架」，确认紫色的手部连线跟上了你的手
- 思考 / 捧腹 / 仰天三个姿势里，奶龙的手型有各自的造型，真实手腕会在造型上叠加；抬腕、压腕按相对幅度反映。手腕是相对手出现那一刻的朝向算的，转动手臂本身不会带动奶龙的手腕，只有手腕自己弯才动

**分数一直不高**
- 先确认首页选中的挑战和你正在做的动作一致
- 思考挑战要闭嘴、睁眼；笑的两个挑战要张大嘴、眯眼
- 眼睛眯起来（真笑时眼角会挤）
- 光线均匀、正对镜头，效果最好

**端口被占用**
`server.py` 会从 8899 开始自动找下一个可用端口；`start.ps1` 固定使用 8899。若被占用，先运行 `stop.ps1`，或手动执行 `python server.py` 查看实际端口。

## 隐私

- 摄像头视频只在浏览器内存中处理，不会写入磁盘、不会上传。
- 没有业务后端；`server.py` 只负责提供静态文件。
- 本地服务器的 CSP 把网络请求限制在 `'self'`，同时阻止了 MediaPipe 官方包自带的性能遥测端点（`odml.pa.googleapis.com`）。所有模型和 wasm 都在本地。
- 最佳成绩按挑战存在浏览器 `localStorage` 中，可在浏览器设置里清除。
- 摄像头权限只在点击开始后请求；回首页会自动关闭摄像头；拒绝权限也可以玩「演示模式」。

纯逻辑测试（Node）：

```powershell
npm test
# 或

```

覆盖：

- 镜像后的手臂角度方向、歪头/肩线角度归一化
- 16:9 下的眼睛开合几何、张嘴不污染咧嘴
- 双手侧别、下巴距离、握拳/张开开合度、手腕兜底
- 头部矩阵偏航 / 俯仰，以及面部几何兜底
- 身体转身 / 前倾、手腕屈伸 / 侧偏的相对增量（含手臂转动补偿，纯转手臂不产生增量）
- 三个挑战的满分、缺手不影响分数、缺上半身（最多 85）、思考不要求躯干
- 中性表情低分
- S/A/B/C/D 等级边界

浏览器端已验证：GPU 下三个模型加载、三个挑战自动演示满分并触发完美模仿、目标图切换、手部 21 点识别（真人手部图片）、摄像头启停、提前结束不记纪录、帮助暂停。3D 版本另外验证了三张参考姿势的实时渲染、脖子 / 身体 / 手腕各方向自由度、无 WebGL / `?no3d=1` 时自动切回 2D、手机首页无横向溢出、页面无脚本报错。

口腔穿模回归也做成了可复现的检查：`tools/preview-3d.html` 支持 `?view=game`（与游戏同机位）、`?mode=head-pitch`，并能用 `window.__stateOverride` 灌入真实游戏的一帧状态；仰头 / 低头 / 转头 / 歪头四种极端姿态下，黑嘴内部都不再漏出黄脸。相关 Playwright 脚本和临时素材未包含在交付目录中。
